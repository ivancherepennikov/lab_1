# Журнал экспериментов с промтами (реальные прогоны)

Методика: «свежий» агент без контекста разговора читает файл промта как свой системный промт, получает одинаковое
описание задачи (`task_fibonacci.md`) и чистую копию проекта; результат оценивается одним и тем же набором:
контрактные юнит-тесты (эталон — независимая Python-модель), статическая проверка добавленных строк, сборка xcodebuild.

## Прогон 0 — промт P0 (штатная сборка курса `creative_c_coder`), модель Sonnet
- Дефект сборщика: в `Agents/creative_c_coder.md` имя `Roles/coder-с.md` содержит кириллическую «с» (U+0441),
  реальный файл `coder-c.md` — латинская. `builder.py` печатает предупреждение и пропускает роль coder.
- Результат: сборка успешна; контрактные тесты: ПРОЙДЕНЫ (код возврата 0); мутационная проверка набора тестов
  (неверная маска по умолчанию) ловится кодом 4.
- Замечания статики: `void**` в сигнатурах QueryInterface (стиль шаблона визарда, правило c.md запрещает `void*`);
  оставлена заглушка интерфейса визарда `IEcoFibonacciLFSR1.h` (не реализуется, но подключается через Id-заголовок).

## Прогон 1 — промт P0, модель Haiku (слабая модель, целевая для курса)
- Сборка библиотеки: успешна (агент сообщил «Implementation completed successfully»); тестов агент не запускал.
- Контрактные тесты: ПАДЕНИЕ (Abort trap 6, код 134).
- Причина (найдена разбором кода): в методах ВТОРОГО интерфейса (`OOA_QueryInterface/AddRef/Release/Init/Next/get_Name`)
  параметр `me` приведён прямо к базе объекта `(CX*)me`, хотя `me` указывает на второе поле-vtable, а не на начало
  структуры; адрес сдвинут на sizeof(указателя), портятся счётчик ссылок и состояние.
- Статика: суффиксы `ULL` у 64-битных констант (не C89).
- Вывод: штатный промт не содержит правила про преобразование `me` во вторичных интерфейсах и про C89-константы;
  сильная модель (Sonnet) справилась сама, слабая нет.

## Прогон 3 — промт P1, модель Haiku, задача Galois LFSR
- Сборка успешна, статическая проверка: 0 нарушений, агент отчитался по чек-листу «всё пройдено».
- Контрактные тесты: ПАДЕНИЕ (Bus error, код 138).
- Причина: агент без необходимости переписал шаблонную фабрику (из-за буквального прочтения запрета «присваивание структур»;
  в шаблоне структура копируется штатно через `pIMem->pVTbl->Copy`, это не libc) и при этом вместо `me = (IEcoUnknown*)pCObj`
  (адрес поля-таблицы) передал в `QueryInterface/Release` ЗНАЧЕНИЕ поля `pCObj->m_pVTbl…` (указатель на таблицу).
  Объект портится. Чек-лист P1 этого не ловит.
- Вывод: нужно (а) запретить трогать шаблонный код фабрики и (б) явно различать «указатель на интерфейс = адрес поля-таблицы» и «значение поля = указатель на таблицу».

## Прогон 7 — промт P2, модель Haiku, задача Xorshift (проверка регресса)
- Сборка успешна, статика: 0 нарушений, агент отчитался «всё пройдено».
- Контрактные тесты: ПАДЕНИЕ (Segmentation fault, код 139) — при том, что на P1 тот же компонент проходил.
- Причина: двусмысленность в МОЁМ правиле P1/P2 («метод k-го интерфейса, k = 1, 2, ...»). Модель нумеровала интерфейсы с единицы:
  в методах первого интерфейса (Service) вычла `1 * sizeof(voidptr_t)`, в методах второго (OOA) — `2 * sizeof(voidptr_t)`;
  правильно: 0 для первого интерфейса и 1 для второго. Ошибка — в промте, а не в «глупости» модели.
- Вывод: нумерацию нужно задавать явно с нуля и привести готовый пример для случая двух интерфейсов; один прогон на ячейку не даёт
  оценки надёжности — правило формулируется однозначно, затем проверка повторяется.

## Прогон 5 — промт P2, модель Haiku, задача Galois LFSR
- Сборка успешна, статика 0 нарушений. Контрактные тесты: НЕ ПРОЙДЕНЫ, код 127 = проверка №127 набора Service
  (`Step32(state=0x10000, param=0xB400)` должен вернуть ERR_ECO_INVALIDARG).
- Причина: `Step32` не усекает состояние до разрядности, заданной старшим битом маски (в ТЗ это требование было); при этом OOA-часть корректна.

## Прогон 6 — промт P2, модель Haiku, задача Fibonacci LFSR (проверка регресса)
- Сборка успешна. Контрактные тесты: НЕ ПРОЙДЕНЫ, код 146 = проверка №46 набора OOA (первое значение для seed 0xDEADBEEF, маска по умолчанию).
- Причина: в `Next` результат усекается маской ширины только при `width < bits`; при ширине 32 в 64-битном хранилище бит 32 остаётся,
  значение выходит за разрядность. SOA-путь (`Step32`) при этом верен: формула шага продублирована в двух местах и разошлась.
- Статика: 2 приведения `(void**)` в шаблонном `Init` (стиль шаблона).

## Вывод по прогонам 5-7 (P2)
Три разные ошибки, ни одна не относится к добавленным в P2 правилам: (1) двусмысленная нумерация интерфейсов в самом правиле (прогон 7),
(2) пропущенное усечение до разрядности регистра (прогоны 5 и 6), (3) дублирование формулы шага в Service и OOA. На P1 два из трёх прогонов проходили,
на P2 ни один (n = 1 на ячейку: разброс слабой модели велик, поэтому правила усиливаются от причин сбоев, а не подгоняются под одну попытку).
Решение для P3: однозначная нумерация с нуля и готовый пример; ОДНА функция шага для Service и OOA; обязательное усечение входа и результата маской ширины.

## Прогоны 8-10 — промт P3 (однозначная нумерация интерфейсов, одна функция шага, обязательное усечение), модель Haiku
Оценка набором с печатью секции/номера проверки (в тестовом клиенте разрешён libc printf; в компонентах нет).
- Прогон 8, Galois: сборка ок, статика 0; ПАДЕНИЕ `service check #127` (`Step32(state=0x10000, param=0xB400)` должен дать INVALIDARG).
  Причина: усечение сделано по разрядности вызова `bits` (32), а не по степени полинома из маски (n = 16), хотя правило 4b это требует.
  (Тот же сбой в прогоне 5 — на P2. Номер 127 в прогоне 5 исходно читался неоднозначно из-за кодировки кода возврата: в наборе Service больше 100 проверок;
  тестовый клиент переделан: код возврата 1/2/3 = секция, подробности печатаются.)
- Прогон 9, Fibonacci: сборка ок, статика 0; ПАДЕНИЕ `cannot get object interface, result=-23` (ERR_ECO_COMPONENT_NOTFOUND).
  Причина: `QueryInterface` каждого интерфейса знает только себя и IEcoUnknown (в Service нет ветки для IEcoPseudoRandom1, в OOA — для Service);
  фабрика не может отдать второй интерфейс. Нарушено правило лекции 3 «из любого интерфейса можно получить любой».
  Агент также без нужды правил фабрику (косметика, на сбой не влияет).
- Прогон 10, Xorshift: сборка ок, статика 0; контрактные тесты ПРОЙДЕНЫ.

## Прогоны 11-13 — промт P4 (P3 + полнота QueryInterface + пример разрядности из маски + запрет правок фабрики), модель Haiku
- Прогон 11, Galois: сборка ок, статика 0, контрактные тесты ПРОЙДЕНЫ (включая период 65535 для 16-битной маски).
- Прогон 12, Fibonacci: сборка ок, статика 0; ПАДЕНИЕ `service check #22` (первое значение при маске 0xB400).
  Причина: функция шага принимает `bits` и строит маску ширины только из него; степень маски не вычисляется вообще.
  Словесное правило с числовым примером (п. 4b) модель не удержала.
- Прогон 13, Xorshift: сборка ок, статика 0, контрактные тесты ПРОЙДЕНЫ.
- Решение для P5: вместо словесного правила дать скелет функции шага LFSR (подстановка маски по умолчанию -> степень -> маска ширины -> усечение входа -> формула -> усечение результата).

## Прогоны 14-16 — промт P5 (P4 + скелет функции шага LFSR), модель Haiku
- Прогон 14, Galois: сборка ок, статика 0; ПАДЕНИЕ Bus error (код 138), вывода теста нет.
  Причина: при «уборке» агент удалил из структуры объекта шаблонные поля `Init/Create/Delete` (указатели на функции), а фабрика (не менялась)
  вызывает `pCObj->Create/Init`: смещения не совпадают с глобальным объектом. Новый тип ошибки: правка заголовка компонента, а не логики.
- Прогон 15, Fibonacci: сборка ок, статика 0; все контрактные проверки пройдены (PASS), затем ПАДЕНИЕ при освобождении (Abort trap, код 134).
  Причина: глобальный объект инициализирован `m_Name = g_FibonacciLFSRName` (статическая строка), а шаблонный `Delete` вызывает `Free(m_Name)` через аллокатор.
  Освобождение статической строки аварийно завершает программу. Тест проверяет также корректное завершение, поэтому дефект пойман.
- Прогон 16, Xorshift: сборка ок; контрактные тесты ПРОЙДЕНЫ; статика: 2 косметических `(void**)` в шаблонном `Init`.
- Скелет функции шага сработал: степень маски и усечение теперь у всех трёх выполнены правильно (раньше ошибались Galois и Fibonacci).
- Решение для P6: правила про структуру (только добавлять поля) и про `m_Name` (статическую строку не записывать в `m_Name`).

## Прогоны 17-19 — промт P6 (P5 + сохранность структуры объекта + статическая строка имени), модель Haiku
- Прогон 17, Galois: сборка ок, статика 0, контрактные тесты ПРОЙДЕНЫ (включая корректное завершение).
- Прогон 18, Fibonacci: сборка ок, контрактные тесты ПРОЙДЕНЫ; статика: 2 косметических `(void**)` в шаблонном `Init`.
- Прогон 19, Xorshift: сборка ок, статика 0; ПАДЕНИЕ `service check #6` (третье значение последовательности seed = 1).
  Причина: недостаток в МОЁМ скелете п. 4c: он требует усечь только итоговый результат `r & wmask`; у Xorshift 32-бит в 64-битном контейнере
  результат КАЖДОГО сдвига влево нужно усекать сразу, иначе старшие биты попадают в последующий `>> 17` и значения расходятся.
- Решение для P7: скелет требует усекать результат каждого сдвига влево внутри формулы.

## Интеграционная находка (при сборке клиента «Калькулятор» из трёх компонентов)
Компоненты, прошедшие контрактные тесты ПО ОДНОМУ, при линковке в один бинарник вели себя неверно: Galois выдавал последовательность Fibonacci,
`get_Name` возвращал пустую строку. Причина: библиотеки Fibonacci и Galois экспортировали одинаковые глобальные имена таблиц функций
`g_xIEcoPseudoRandom1VTbl` и `g_xIEcoPseudoRandomService1VTbl` (агенты назвали их без суффикса CID); линковщик связал глобальный объект Galois с таблицами Fibonacci.
- Исправление в основных проектах: суффикс последних 8 символов CID (`..._86F04FDE`, `..._BFF2763F`), после этого дубликатов `nm -g` нет, демонстрация корректна.
- Вывод: нужна проверка уникальности глобальных символов между компонентами (добавлена в `tests/evaluate_run.sh`) и правило в промте:
  любое имя с внешней видимостью получает суффикс CID, остальное делается `static` (правило добавлено в P8).
