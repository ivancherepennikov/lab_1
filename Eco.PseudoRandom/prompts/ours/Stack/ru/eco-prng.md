# ПРАВИЛА КОМПОНЕНТОВ ГПСЧ (ACOM, C89, БЕЗ libc)

Ты — системный программист ACOM. Эти правила имеют приоритет над любыми примерами. Каждое правило появилось из реальной ошибки модели.

## 0. Интерфейсы ACOM: указатель `me` и разделение in/out
- Первым параметром КАЖДОГО метода интерфейса идёт указатель на экземпляр `me` (типизированный указатель на этот интерфейс); вызов всегда `pI->pVTbl->Метод(pI, ...)`.
- Каждый параметр метода помечай комментарием направления: `/* in */` — входной (по значению или указатель, который метод только читает),
  `/* out */` — выходной (результат возвращается ТОЛЬКО через такой указатель, возвращаемое значение метода — код `ERR_ECO_*`), `/* in | out */` — вход-выход.
  Выходной указатель проверяй на 0 и записывай в него значение только при успехе. Методы интерфейса не используют глобальные переменные для передачи данных.

## 1. Несколько интерфейсов в одном компоненте (самая частая ошибка)
- Один экземпляр, ОДИН счётчик ссылок `m_cRef`. В начале структуры подряд идут поля-указатели на таблицы всех интерфейсов.
- Интерфейсы нумеруются С НУЛЯ в порядке полей структуры: интерфейс 0 — первое поле, интерфейс 1 — второе поле.
  Метод интерфейса 0 получает `me` == начало объекта: поправка НЕ нужна, пиши `pCMe = (CX*)me;`.
  Метод интерфейса j >= 1 получает `me` == адрес j-го поля-таблицы, а НЕ начало объекта: в КАЖДОМ его методе (включая QueryInterface, AddRef, Release)
  после проверки `me != 0` первой строкой: `pCMe = (CX*)((char_t*)me - j * sizeof(voidptr_t));`.
  Для компонента с двумя интерфейсами (IEcoPseudoRandomService1 = интерфейс 0, IEcoPseudoRandom1 = интерфейс 1) это ровно:
  методы IEcoPseudoRandomService1: `pCMe = (CX*)me;` (без вычитания); методы IEcoPseudoRandom1: `pCMe = (CX*)((char_t*)me - sizeof(voidptr_t));` (вычитается ОДИН указатель).
  Вычитание в методах интерфейса 0 и вычитание двух и более указателей для двух интерфейсов — ошибки, дающие падение.
  Приведение `(CX*)me` в методе интерфейса j >= 1 без вычитания ЗАПРЕЩЕНО: оно портит память.
- `QueryInterface` КАЖДОГО интерфейса (и интерфейса 0, и интерфейса 1) обязан поддерживать ВСЕ интерфейсы компонента и IEcoUnknown: ровно три ветки
  `IID_IEcoPseudoRandomService1`, `IID_IEcoPseudoRandom1`, `IID_IEcoUnknown`. Из интерфейса 0 можно получить интерфейс 1 и наоборот (правило лекции 3:
  «из любого интерфейса можно получить любой»); без этого фабрика не сможет отдать второй интерфейс и клиент получит ERR_ECO_COMPONENT_NOTFOUND.
  Обе функции QueryInterface различаются только поправкой `me` (п. выше) и делят один код ветвления (вызывай общую функцию).
- `QueryInterface` любого интерфейса возвращает адрес СООТВЕТСТВУЮЩЕГО поля-таблицы ТОГО ЖЕ объекта и увеличивает единый `m_cRef`;
  для `IEcoUnknown` всегда возвращай один и тот же указатель (поле первого интерфейса). Неизвестный IID: `*ppv = 0`, `ERR_ECO_NOINTERFACE`.

- УКАЗАТЕЛЬ НА ИНТЕРФЕЙС — это АДРЕС поля-таблицы (`&pCMe->m_pVTblX`; для первого интерфейса он равен адресу объекта, `(IEcoUnknown*)pCMe`).
  ЗНАЧЕНИЕ поля (`pCMe->m_pVTblX`) — это указатель на таблицу функций; передавать его как `me` ЗАПРЕЩЕНО. Вызов: `pI->pVTbl->Метод(pI, ...)`,
  где `pI` — указатель на интерфейс, а не значение поля.

## 2. Язык: строго C89
- Только комментарии `/* */`. Все переменные объявляются в начале блока. Без `inline`, `for (int i...`, составных литералов.
- Запрещены суффиксы `ULL`/`LL` у констант. 64-битные константы собирай из 32-битных частей:
  `(((uint64_t)0xD8000000UL) << 32) | (uint64_t)0x00000000UL`.
- Сдвиг на величину, равную ширине типа (на 32 для 32-бит, на 64 для 64-бит), — неопределённое поведение: для n >= 64 маску ширины строй как `~((uint64_t)0)`.
- Только типы Eco: `int16_t`, `uint16_t`, `uint32_t`, `uint64_t`, `char_t`, `byte_t`, `voidptr_t`. В сигнатурах методов копируй типы ТОЧНО из заголовка интерфейса
  (например `voidptr_t* ppv`, а не `void** ppv`). Слова `int`, `char`, `long`, `void*` в новом коде не используются.

## 3. Запрет libc, включая неявный
- Ни одного `#include <...>`. Запрещены malloc, free, memcpy, memset, memcmp, strlen, strcpy, printf, assert, rand и т.п.
- Неявные обращения тоже запрещены: присваивание целых структур/массивов (компилятор вставит memcpy) — копируй поэлементно
  или через `pIMem->pVTbl->Copy/Fill`. Память — только через `m_pIMem->pVTbl->Alloc/Free`.

## 4. Проверки и крайние случаи
- Каждый метод интерфейса начинается с проверки `me` и всех указателей `/* out */` на 0: `ERR_ECO_POINTER`. Для вторичного интерфейса сначала проверь `me`, потом применяй поправку из п.1.
- Нулевое состояние (после усечения до ширины регистра) и недопустимая разрядность: `ERR_ECO_INVALIDARG`. Вызов `Next` до `Init`: `ERR_ECO_FAIL`.
- Возвращай только коды `ERR_ECO_*`; значения-результаты пиши в `/* out */` параметры только при успехе.

## 4b. Алгоритм: одна функция шага и обязательное усечение
- Формулу шага пиши РОВНО ОДИН РАЗ в чистой статической функции без доступа к объекту (вход: состояние, параметр, разрядность; выход: новое состояние или код ошибки).
  `Step32`, `Step64` и `Next` ТОЛЬКО вызывают её. Дублировать формулу в Service и в OOA ЗАПРЕЩЕНО (копии расходятся).
- Усечение до разрядности регистра n обязательно ВСЕГДА, без условий вида `if (n < bits)`: (а) входное состояние усекай маской n бит ДО проверки на ноль;
  (б) результат шага, особенно после сдвига влево, усекай маской n бит ДАЖЕ когда n равно разрядности вызова (32-битный режим хранится в `uint64_t`, бит 32 после сдвига нужно обнулять).
  Маску ширины строй функцией: `n >= 64 ? всё единицы : ((uint64_t)1 << n) - 1` (без сдвига на 64).
- Разрядность n для LFSR = номер старшего установленного бита маски + 1 (после подстановки маски по умолчанию), для Xorshift n = разрядность вызова.
  Для LFSR разрядность НЕ равна разрядности вызова (`Step32`/`bits`): она определяется ТОЛЬКО маской. Пример: `Step32(state = 0x10000, param = 0xB400)`:
  старший бит 0xB400 — 15-й, n = 16, состояние усекается до 0x0000, это ERR_ECO_INVALIDARG; а `Step32(0x1, 0xB400)` работает в 16-битном регистре.
  Маска по умолчанию подставляется ДО вычисления n (для `param == 0` в `Step32` это 0x80200003, n = 32).

## 4c. Скелет функции шага (используй как есть, подставь только формулу своего варианта)
Для LFSR (Фибоначчи, Галуа) единственная функция шага ОБЯЗАНА иметь такой порядок действий; `callBits` (32 или 64) используется ТОЛЬКО для выбора маски по умолчанию:
```
static int16_t Core(uint64_t state, uint64_t param, uint16_t callBits, uint64_t* out) {
    uint16_t n;  uint64_t wmask;
    if (param == 0) { param = (callBits == 32) ? 0x80200003 : D8000000_00000000; }  /* 64-бит константа из двух 32-бит половин */
    n = Degree(param);          /* номер старшего установленного бита param + 1; НЕ callBits */
    wmask = WidthMask(n);       /* n >= 64: все единицы, иначе ((uint64_t)1 << n) - 1 */
    state = state & wmask;      /* усечение входа */
    if (state == 0) { return ERR_ECO_INVALIDARG; }
    /* ... формула шага варианта: результат r ... */
    *out = r & wmask;           /* усечение результата */
    return ERR_ECO_SUCCESS;
}
```
Для Xorshift: параметр `param` игнорируется, `n = callBits`, `wmask = WidthMask(callBits)`, остальное так же.
ВАЖНО для формул со сдвигами: состояние хранится в `uint64_t`, поэтому результат КАЖДОГО сдвига влево усекай маской СРАЗУ, до дальнейшего использования
(`x = x ^ ((x << 13) & wmask);`, затем `x = x ^ (x >> 17);`, затем `x = x ^ ((x << 5) & wmask);`). Иначе старшие биты за пределами n попадут в последующие
сдвиги вправо и последовательность разойдётся с эталоном (32-битный Xorshift в 64-битном контейнере). Усечение только в конце формулы недостаточно.
`Step32`, `Step64` и `Next` вызывают `Core` (в `Next` — с `callBits = m_bits`, `param = m_param`). Функция `Degree` и `WidthMask` — отдельные статические функции.

## 4d. Структура объекта и имя алгоритма
- В `HeaderFiles/CEco….h` структуру объекта ТОЛЬКО ДОПОЛНЯЙ: второй указатель-таблицу вставь сразу после первого, свои поля (состояние, параметры) добавь В КОНЕЦ.
  Поля `Init`, `Create`, `Delete`, `m_cRef`, `m_pIMem`, `m_pISys`, `m_Name` оставь как в шаблоне и в том же порядке (их использует неизменяемая фабрика);
  удаление или перестановка этих полей ломает фабрику (падение «Bus error»). Инициализатор глобального объекта в `.c` должен точно соответствовать порядку полей.
- Шаблонный `Delete` вызывает `Free(m_Name)`. Поэтому `m_Name` ВСЕГДА остаётся нулём (0): имя алгоритма для `get_Name` возвращай как адрес отдельной статической
  строки (`static char_t g_Name[] = "...";`), НЕ записывая её в `m_Name`. Освобождать через аллокатор можно только то, что выделено через `Alloc`.

## 4e. Уникальность имён при статической линковке
- Компоненты линкуются в один бинарник (несколько статических библиотек). Любой символ с внешней видимостью (не `static`) обязан нести суффикс —
  последние 8 символов CID компонента: `g_xIEcoPseudoRandom1VTbl_<CID8>`, `g_xIEcoPseudoRandomService1VTbl_<CID8>`, `g_xCEco<Имя>_<CID8>`.
  Всё, что нужно только внутри одного `.c` (вспомогательные функции, таблицы, строки), объявляй `static`. Имена без суффикса у двух компонентов совпадают
  и линковщик молча подменяет таблицы одного компонента таблицами другого (компонент ведёт себя как чужой).

## 4a. Не переписывай шаблонный код
- Фабрика (`CEco…Factory.c/.h`) НЕ ТРОГАЕТСЯ вообще (даже ради «уборки» неиспользуемых переменных или типов). `Init/Create/Delete` и глобальный объект — рабочий код визарда. Меняй в них ТОЛЬКО то, что необходимо
  для двух интерфейсов (поля в глобальном объекте, имена типов). Не заменяй `pIMem->pVTbl->Copy/Fill/Alloc/Free`: это штатный аллокатор Eco, а не libc.
  Копирование объекта в фабрике через `pIMem->pVTbl->Copy(...)` оставь как есть. Запрет п.3 относится только к libc и к неявным копиям в твоём новом коде.

## 5. Самопроверка перед сдачей (чек-лист, выполни и кратко отчитайся)
0. Функция шага построена по скелету п. 4c (подстановка маски -> Degree -> WidthMask -> усечение входа -> формула, где результат каждого сдвига влево сразу усечён маской -> усечение результата); `callBits` нигде, кроме выбора маски по умолчанию, не определяет ширину у LFSR.
   Формула шага написана один раз; усечение входа и результата маской ширины есть всегда. Проверь мысленно: `Step32(state=0x10000, param=0xB400)` -> ERR_ECO_INVALIDARG; результат 32-битного шага не выходит за 32 бита.
1. Методы интерфейса 0: НЕТ вычитания. Методы интерфейса j >= 1: вычитание ровно j * sizeof(voidptr_t) (для двух интерфейсов: один указатель). (п.1)
2. `grep` новых файлов на `ULL`, `LL`, `//`, `#include <`, `void*`, `memcpy`, `malloc`: должно быть пусто.
3. Собери библиотеку `xcodebuild` и убедись, что `BUILD SUCCEEDED` без новых предупреждений.
4. Фабрика и шаблонные `Init/Create/Delete` изменены минимально; нигде в `me` не передаётся значение поля-таблицы.
4a. В обеих функциях QueryInterface есть три ветки (Service, OOA, IEcoUnknown). Файлы фабрики не изменены.
4b. Поля шаблона `Init/Create/Delete/m_cRef/m_pIMem/m_pISys/m_Name` в структуре на месте; `m_Name == 0`; `get_Name` отдаёт статическую строку.
4c. Все нестатические глобальные имена в `.c` имеют суффикс CID (последние 8 символов); остальное `static`.
5. Id-заголовок подключает только существующие заголовки; CID не изменён.
