# Лабораторная работа 1 – генераторы псевдослучайных чисел на АОМК (ACOM)

Раздел 3, задачи **38–40**: LFSR в конфигурации Фибоначчи, LFSR в конфигурации Галуа и Xorshift – как три независимых компонента технологии АОМК (ACOM, Eco.Framework) с динамическим переключением в клиенте. Каждый компонент реализован двумя способами одновременно: **SOA** (без состояния) и **ООА** (состояние внутри объекта).

Платформа: macOS (arm64), Xcode, язык C89. Компоненты не используют libc.

## Что в репозитории

| Папка | Содержимое |
|---|---|
| `Eco.FibonacciLFSR1/` | компонент задачи 38 (исходники, `BuildFiles/Mac` – собранные статические библиотеки, проекты Xcode, юнит-тест) |
| `Eco.GaloisLFSR1/` | компонент задачи 39 |
| `Eco.Xorshift1/` | компонент задачи 40 |
| `Eco.Lab1/` | консольный клиент «Калькулятор» (`UnitTestFiles/SourceFiles/EcoLab1.c`) |
| `Eco.PseudoRandom/SharedFiles/` | общие интерфейсы и IDL (мастер-копия; копии лежат в каждом проекте) |
| `Eco.PseudoRandom/tests/` | контрактные тесты, установка тестов в проект, скрипты запуска и оценки |
| `Eco.PseudoRandom/reference/` | независимая эталонная модель на Python и генератор тестовых векторов |
| `Eco.PseudoRandom/prompts/` | системные промты P0–P9, журнал экспериментов, задания агентам |
| `Eco.PseudoRandom/report/` | отчёт `Report_Lab1_PRNG.docx` и скрипты, которыми он собран |

Проекты лежат рядом друг с другом на одном уровне, потому что клиент подключает компоненты по относительным путям (`../../../../Eco.GaloisLFSR1/...`). Структуру папок менять не нужно.

## Архитектура

Все три алгоритма реализуют один и тот же контракт из двух интерфейсов, поэтому алгоритм в клиенте меняется заменой CID.

| Интерфейс | Методы | Роль |
|---|---|---|
| `IEcoPseudoRandomService1` | `Step32`, `Step64` | SOA: состояние передаёт клиент |
| `IEcoPseudoRandom1` | `Init`, `Next`, `get_Name` | ООА: состояние хранит объект |

| Задача | Компонент | CID |
|---|---|---|
| 38 | `Eco.FibonacciLFSR1` | `A0F26A7C-E65B-43D8-B022-EFFE919D0053` |
| 39 | `Eco.GaloisLFSR1` | `09232D50-25AE-4DC5-B118-44D166391FF5` |
| 40 | `Eco.Xorshift1` | `EB9A5A10-5897-45BE-90FE-DB27479BCC71` |

Для LFSR параметр `param` – маска отводов (бит i соответствует члену x^(i+1)), разрядность регистра определяется старшим установленным битом маски, `param = 0` выбирает полином по умолчанию (0x80200003 для 32 бит, 0xD800000000000000 для 64 бит). Для Xorshift `param` игнорируется. Нулевое состояние отвергается (`ERR_ECO_INVALIDARG`). Подробности контракта – в комментариях `Eco.PseudoRandom/SharedFiles/IEcoPseudoRandom*.h`, обоснование и сравнение подходов – в отчёте.

## Сборка и запуск

Нужны macOS на arm64 и Xcode. Фреймворк **Eco.Framework** в репозиторий не входит (материалы курса): распакуйте его и задайте путь.

```bash
export ECO_FRAMEWORK=$HOME/Dev/Eco.Framework   # путь к вашей копии Eco.Framework

# компонент (Debug и Release); так же для Eco.FibonacciLFSR1 и Eco.Xorshift1
cd Eco.GaloisLFSR1/AssemblyFiles/Mac/Xcode_v123
xcodebuild -project EcoGaloisLFSR1.xcodeproj -scheme Static -configuration Release build
cd -

# клиент «Калькулятор»
cd Eco.Lab1/AssemblyFiles/Mac/Xcode_v123
xcodebuild -project EcoLab1UnitTest.xcodeproj -scheme Static -configuration Release \
           -derivedDataPath ../../../.dd_client build
cd -

./Eco.Lab1/.dd_client/Build/Products/Release/Static
```

Клиент сначала печатает демонстрацию (для каждого алгоритма и разрядности последовательности SOA и ООА и признак их совпадения), затем запускает интерактивное меню: выбор алгоритма, режима, разрядности, начального состояния (hex), маски и количества значений. Пункт **8** сравнивает генераторы со стандартной библиотекой C, пункт **9** печатает статистику качества и скорость. Конец ввода завершает программу:

```bash
./Eco.Lab1/.dd_client/Build/Products/Release/Static </dev/null     # только демонстрация
printf '9\n0\n' | ./Eco.Lab1/.dd_client/Build/Products/Release/Static   # статистика
```

В Xcode (без командной строки) путь к фреймворку задаётся один раз: Xcode → Settings → Locations → Custom Paths, имя `ECO_FRAMEWORK`.

## Тесты

Один и тот же контрактный набор (`Eco.PseudoRandom/tests/PseudoRandomTests.h`) выполняется для каждого компонента; ожидаемые значения генерирует независимая модель `Eco.PseudoRandom/reference/reference.py` (она сверена с опубликованными значениями Xorshift Марсальи: при начальном состоянии 1 – 270369, 67634689, 2647435461).

```bash
Eco.PseudoRandom/tests/run_unittest.sh Eco.GaloisLFSR1    # соберёт библиотеку и тест, запустит его
```

Ожидаемый результат: `PASS: all 65816 contract checks passed` у LFSR (в том числе полный цикл периода 65535) и `PASS: all 279 contract checks passed` у Xorshift. Набор проверяет значения через SOA и ООА, ошибочные аргументы и нулевые указатели, `Next` до `Init`, правила QueryInterface/AddRef/Release и корректное завершение.

## Результаты

Сравнение значений компонентов с эталоном: **14 из 14** комбинаций (алгоритм × разрядность × seed × маска), расхождений нет (и для SOA, и для ООА).

Статистика на 1 000 000 значений (режим ООА, seed 0x2545F491, полином по умолчанию; macOS arm64, Release). «Доля единиц» идеально 0,5; хи-квадрат по 256 значениям байта идеально около 255; скорость в млн значений в секунду:

| Алгоритм | Бит | Доля единиц | Хи-квадрат | ООА, млн/с | SOA, млн/с |
|---|---|---|---|---|---|
| Fibonacci LFSR | 32 | 0.49977 | 833.6 | 67 | 78 |
| Fibonacci LFSR | 64 | 0.49987 | 1727.7 | 40 | 43 |
| Galois LFSR | 32 | 0.50034 | 384.7 | 73 | 81 |
| Galois LFSR | 64 | 0.49946 | 1545.0 | 41 | 44 |
| Xorshift | 32 | 0.50005 | 315.8 | 139 | 265 |
| Xorshift | 64 | 0.50001 | 234.3 | 142 | 277 |

Выходное значение – состояние регистра целиком, поэтому у LFSR байтовая равномерность хуже, чем у Xorshift (последовательные состояния сдвинуты на один разряд); побитовое распределение сбалансировано у всех. Размер объекта компонента: 96 байт у LFSR и 88 байт у Xorshift (у шаблонного объекта визарда 64 байта).


### Сравнение со стандартной библиотекой C и MATLAB-аналогом

Побитовое сравнение значений с `rand`/`random`/`lrand48` невозможно (другие алгоритмы), поэтому генераторы сравниваются на одинаковых тестах: пункт **8** меню клиента вычисляет по младшим 24 битам миллиона значений долю единиц и хи-квадрат по двум байтам. Mersenne Twister (генератор `rand` в MATLAB по умолчанию, в Python – `random`) оценён скриптом `Eco.PseudoRandom/report/collect_data.py` по тем же формулам.

| Генератор | Доля единиц | Хи-квадрат, байт 0 | Хи-квадрат, байт 1 | Скорость, млн/с |
|---|---|---|---|---|
| Fibonacci LFSR | 0.49977 | 208.3 | 208.3 | 65 |
| Galois LFSR | 0.50043 | 300.2 | 296.2 | 73 |
| Xorshift | 0.50009 | 242.4 | 258.9 | 139 |
| libc rand() | 0.49999 | 263.6 | 233.2 | 140 |
| libc random() | 0.50017 | 227.8 | 213.4 | 321 |
| libc lrand48() | 0.49984 | 252.0 | 261.8 | 362 |
| Mersenne Twister (MATLAB rand, Python random) | 0.50005 | 245.0 | 253.9 | – |

По качеству компоненты не уступают стандартным генераторам (хи-квадрат идеально около 255, порог 1 % около 310). По скорости libc быстрее: он вызывается напрямую, а компонент – через таблицу виртуальных функций интерфейса АОМК.

## Промты и ИИ-генерация

Код компонентов сгенерирован ИИ-агентами, а не написан вручную; ответственность за корректность лежит на проверке. Разрабатывался и проверялся **системный промт**: собирается из модулей курса (`Eco.AI.Promts`) и собственного модуля `Eco.PseudoRandom/prompts/ours/Stack/ru/eco-prng.md`. Версии P0–P9 и результаты 29 прогонов (по причинам каждой ошибки ИИ) записаны в `Eco.PseudoRandom/prompts/experiment_log.md`; финальный текст – `P9_ours.md`.

Метод: «свежий» агент (модель Claude Haiku) получает только файл промта, задание и чистый проект eco-wizard; результат оценивается сборкой, контрактными тестами, статической проверкой запрещённых конструкций и проверкой уникальности глобальных символов. Каждая версия промта проверена одним запуском на задачу, поэтому журнал – история исправлений, а не статистическая оценка надёжности.

Находки: в `Agents/creative_c_coder.md` курса в имени `Roles/coder-с.md` кириллическая «с», из-за чего роль coder не подключается при сборке; компоненты, прошедшие тесты по одному, могли подменять друг друга при линковке в один бинарник из-за одинаковых глобальных имён (исправлено правилом суффикса CID и проверкой символов).

Пересборка промта (нужны `uv` и папка курса `Eco.AI.Promts`): `ECO_PROMTS=/путь/к/Eco.AI.Promts Eco.PseudoRandom/prompts/build_P1.sh P9`.

## Оговорки

- **libc в клиенте.** Консольный клиент и тестовые клиенты используют `printf`, `scanf` и `clock` стандартной библиотеки: для macOS в Eco.Framework нет собранных компонентов `Eco.StdIO.C89`/`Eco.Log1` (только Linux и Windows). Сами компоненты libc не используют: в их библиотеках нет внешних символов.
- В репозиторий не входят Eco.Framework, лекции и материалы курса, а также кэши сборки.
- Скорость LFSR ниже скорости Xorshift: в сгенерированной реализации степень полинома вычисляется циклом при каждом вызове (можно вычислять один раз в `Init`).
